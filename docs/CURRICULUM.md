# 课程数据 v1：专家后缀

这是下一阶段的数据准备，不是课程训练完成的结果。基于已发布的 1000 条完整轨迹，以种子 20260924 按轨迹分为 800 / 100 / 100 条训练、验证、最终测试来源。先划分再展开，避免同一原始轨迹被直接拆进不同集合。

## 生成与检查

在项目根目录运行，不需要 GPU、PyTorch 或 API：

```bash
python -m cube.curriculum
python -m tests.check_curriculum
```

默认输出 `data/curriculum_v1/`，已存在时拒绝覆盖。重建时使用新目录：

```bash
python -m cube.curriculum --output data/curriculum_rebuilt
```

## 数据隔离

- 原 332 个浅层验证起点继续保留。训练候选轨迹若经过任一预留起点，整条排除，避免未来展开其后缀时泄漏。
- 因此 800 条候选训练轨迹中排除 275 条，实际保留 525 条。原始轨迹仍保存在原始数据文件，不移动到其他划分。
- 新验证和最终测试起点均排除当前全部课程训练状态、之前 SFT 1000 个状态，以及旧的 332 个预留起点。
- 最终测试起点还排除验证来源轨迹里的全部非终局状态。
- 每个集合内部按状态去重，选择该集合里观察到的最短专家后缀，并保留来源 ID 和步骤。
- 这是精确状态级的起点隔离，后续还原状态允许重叠，没有排除旋转等价状态。不同后缀可能来自同一原始轨迹，不能把所有评估起点当作相互独立的随机魔方。
- 最终测试数据仅准备，尚未运行模型评估。后续扩大训练数据时需要重新检查与保留测试起点的重叠。

## 输出文件与字段

- `train.jsonl`、`validation.jsonl`、`test.jsonl`：分组后的逐步样本，每行一个状态及其可行后缀。
- `train_upto_3.jsonl`：专家剩余不超过 3 步，共 275 个状态。
- `train_upto_5.jsonl`：专家剩余不超过 5 步，共 1220 个状态。
- `manifest.json`：来源轨迹划分及保留的训练轨迹 ID。
- `report.json`：每层数量、过滤数量和实验边界。

`expert_remaining` 是选择的可行后缀长度，**不代表最短距离**。`optimal_distance` 仅在现有深度 3 的精确 BFS 表覆盖该状态时填写，否则为 null。`solution` / `target_action` / `target_index` 是监督标签，不能作为策略输入。`source_id` / `source_step` 用于追踪来源。

目前阶段文件没有自动混入旧 SFT 数据，也没有新增随机游走样本。现有 `cube.train` 要求浅层最短解格式，`cube.eval` 也面向浅层验证，**请勿直接把这些新文件交给旧训练、评估命令**。
